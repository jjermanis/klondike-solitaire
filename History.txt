Version 01.01	26 minutes dev	2 minutes AI	4 minutes test		32 minutes

The goal for this game is simple. My wife plays solitaire on her tablet. But the
on-line version have repetitive ads. The base solitaire (Klondike) is in the
public domain. I can just create a version of the game (like my wife likes)
without the ads.
I asked Claude to ask me the question it would have for implementing Klondike
Solitaire. It had eight - all were easy to answer. Claude developed the initial
version after this.
It did well. There a couple defects, some other minor changes, but it is
playable as-is.


Version 01.02	11 minutes dev	1 minutes AI	2 minute test		46 minutes

The cards looked odd. There were three suits shown on the card: on corners and
the center. That is accurate, but not needed for a small screen and card. Kept
only the suit in the center. The top number was center-justified. Aligned that 
to the left. Finally, it looked a little small. Enlarged by 50%. This was easily
done in one try with Claude.
One way to move a card that can move is to click on it. This will work, but the
move is instantaneous. I asked Claude to add animation to move it quickly. It
did this well on its first attempt.


Version 01.03	11 minutes dev	0 minutes AI	1 minute test		58 minutes

The next change is to verify when the New Game is pressed. It was working on
any touch, no confirmation. That would result is accidentally ending the game.
If the game is still going and the New Game button is tapped, I want the game
to confirm. This was an easy fix for Claude,


Version 01.04	45 minutes dev	3 minutes AI	3 minutes test		1 hour 49

Testing on an iPad, the game didn't expand to the available space. In general, I
wanted to expand as much as possible in the browser. This took several attempts
to resolve. The initial to resize to the available space (with a certain
minimum) was easy to change. After doing this, the click-and-drag and click to
move was off: the start position was off from it appeared to start. I'm not
going to bother documenting the steps. I'd estimate six iterations for Claude to
get this to work correctly.


Version 01.05	9 minutes dev	1 minute AI	3 minutes test		2 hours 2

I noticed a regression. When moving a card, while the card moves, that card is
still seen in the start location. It doesn't change to the new view until the
card reaches the destination. I asked Claude to address: it was an easy two lines.
Like all web apps, I wanted to add a browser tab icon. Claude suggested an Ace of
Spades card. I tried it and I didn't like it: too small. I switched to just the
Ace of Spades on a transparent background.


Version 01.06	14 minutes dev	1 minute AI	2 minutes test		2 hours 19

This game really needed an Undo button. If there was a move done accidentally,
many of them could not be undone. I asked Claude to add an Undo button. I would
revert to the previous move. That can be repeated to the beginning of the game.
The number of changes were extensive - I'd estimate about 75 lines of code.
But the first change appear to work. It allows Undo for many: draw cards,
moving cards, both within board and to the top-left stocks.


Version 01.07	10 minutes dev	2 minute AI	3 minutes test		2 hours 34

There was a functional defect I wanted to fix. For the columns in the tableau,
you can do more than just move the bottom card. If a card higher in chain of
cards can all move, all the cards should be moveable together. If you click-
and-drag, it works. If you just clip, it does not - only works when you click
at the bottom. I asked Claude to address this. The attempt had a defect. It 
would not move after clicking - not even the very bottom would work. Claude
found the defect it added (one-line change). Now it works for all the desired
cases.


Version 01.08	6 minutes dev	1 minute AI	2 minutes test		2 hours 43

Clicking worked, with a UI tweak: it would only show the bottom card if a stack
got clicked. I asked Claude to resolve. It took some lines of code, but it was
fast and worked the first time.


Version 01.09 	18 minutes dev	2 minutes AI	4 minutes test		3 hours 7

There was a UI oddity at the end of the game. After all the cards are moved up
to the foundation, there are cards that drop from top to bottom. But they didn't
go all the way: the cards would (visibly) stop with about a third of the card
remaining on screen. I asked Claude to change this. It moved the cards down 
further to get them off the screen, and faded the color out toward the bottom.
There were a couple defect to resolve to get this working.
After adding the Undo button, the New Game button moved from center-justified to
right. I asked Claude to move it back to center - it was trivial.
